# Entity Layout 静态区域冲突诊断

## 目标

在现有 `Bing.Offices.Analyzers` 中增加可静态确定的布局区域交叉冲突诊断，提前发现与运行时 `ExcelEntityLayoutBuilder.Build` 一致的合并区域重叠、显式有界列表区域重叠、固定单元格与列表区域重叠，以及列表区域与合并区域重叠。修正文档中过期的最终 Footer 命名锚点说明。

## 范围与约束

1. 只分析直接写在 `ExcelEntity.Layout` 或 `LayoutFromAttributes` 配置委托中的单条 Fluent 调用链、常量工作表和 A1 地址；列表区域仅在同一内联配置中声明常量 `End` 时形成有界矩形。
2. 识别 `LayoutFromAttributes` 的公开实例属性固定单元格，与同一 Fluent 链中的已知列表区域和 Fluent 固定单元格比较。两个 Fluent 固定单元格或两个属性固定单元格的同址冲突继续由现有 `BOE002` 负责；属性与 Fluent 混用时的同址冲突由新诊断负责。固定单元格与合法合并区域左上角不报错。
3. 新增 `BOE005`，错误级别；同一对区域只报告一次，定位到产生交叉的后续声明。变量、条件分支、跨语句构建器状态、模板命名锚点、动态列表高度和列数不推断。
4. 不修改运行时布局、公共导出 API 或包版本。新增分析器职责测试、包消费者负例和文档规则；维护阶段执行记录。分析器包已有发布流程继续使用。

## 验证

先构建分析器并运行双 TFM 职责测试；再打包分析器，从包消费者验证新诊断确实使负例构建失败，同时正常调用不报错。最后运行 Docs 测试、`git diff --check` 和严格 UTF-8/BOM/EOL 检查。运行时路径与公共 API 未改变，复用上一阶段的 Provider 和 API 证据，不重跑无关性能矩阵。
