# 实体布局分组小计与分页组合

Task ID：`BING-OFFICES-GROUP-PAGINATION-20261003-001`

## 目标与现状

使同一 `ExcelEntityListRegionBuilder<TItem>` 能组合 `GroupSubtotal`、`PageBreak` 和可选的 `PageSubtotal`，保持现有单独配置及公开 API 签名不变。当前构建器和布局 Build 明确拒绝组合；NPOI、ClosedXML 各有分组与分页的独立写入分支、行数预检和导入跳过规则。仅删除互斥检查不足以保证行号、公式、区域冲突和回读正确。

## 物理行规则

- 页容量仅计算明细行；分组保持输入顺序，不排序，相同键的连续行构成一组。组可跨页。
- 组结束后写组小计；存在下一页时，若配置页小计，再写当前页小计。同一边界顺序为组小计、页小计、分页符。末页不写页小计。
- 每个小计保留自己的 GapRows、相对单元格、合并及聚合快照。页聚合取该页明细；组聚合取整个连续组；最终 Footer 取全部明细。
- 未配置页小计时仍按明细数分页；若边界恰逢组尾，分页符位于组小计之后。
- 空明细不生成小计或分页符，最终 Footer 沿用现有行为；表头不计入页容量。
- 导入依 marker 精确识别并跳过所有小计区域；页 marker 的间隔必须恰有配置数量的明细，忽略组小计所占行；错误保持结构化配置异常。最终实体和批次 SourceRows 保留工作表原始坐标。

## 实施任务

### P1 共享行规划与构建约束

目标：导出、边界预检和运行时占用范围使用同一行序列。新增 Provider 共享内部行规划器，产出明细段、组/页小计段、分页符及最终 Footer 起始行。移除三项互斥检查，保留 marker 唯一、页小计必须配 PageBreak、公式约束。组合专用路径使用规划器，单独模式原逻辑不变。

验证：表头/无表头、空明细、组跨页、组页同边界、GapRows/多行尾部、分页符及最终 Footer 位置。风险是边界溢出和模板合并，写入前逐段预检。

### P2 两个 Provider 与导入

目标：NPOI XLS/XLSX、ClosedXML XLSX 按共享规划写入并保留模板已有样式和合并；组合导入同时跳过组/页小计，按明细计数验证页 marker。保持取消、流所有权和异步外围 IO 合同。

验证：真实工作簿结构、完整读回、原始行号、缺失/错位 marker、区域/最大行冲突、预取消。NPOI 两种格式均有成功和失败用例。

### P3 文档和交付

目标：中文 XML 注释、Entity Layout 文档示例、生产符号到测试方法映射和 execution。无公共成员增删或改签名；双 TFM API snapshot 成员差异应为零，不借更新基线掩盖差异。

验证：受影响项目双 TFM、Provider 合同、解决方案 Release 构建、`Category!=Large` 常规测试、`git diff --check` 与严格 UTF-8/BOM/EOL 检查。仅在影响证据要求时做更大资源测试，不执行无关大规模性能矩阵。

## 范围与验收

本轮只组合现有三项能力，不新增每页命名锚点、透视表、公式 DSL 或版本号。公开构造、接口及 Fluent 签名兼容；组合工作簿能从两个 Provider 导出再导入，页容量、组/页小计、最终 Footer、分页符和结构化错误与上述规则一致。不自动提交、推送或发布。
