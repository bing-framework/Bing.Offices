## 优先修复 TODO

### FIX-001：固定透视表来源集合

- [ ] 严重程度 MEDIUM；处理要求 SHOULD_FIX。
- 问题：`ExcelWorkbookExportBuilder.Build` 使用同一个 `names` 集合校验来源并添加透视目标，第二个透视表可引用第一个透视目标。
- 证据：`ExcelWorkbookExportBuilder.cs:192`、`:194`；探针 `pivot-source` 的请求构建成功，随后在导出时报告第二个透视表来源表头无效。
- 影响：违反本阶段“来源为已声明业务 Sheet”的约束；非法请求被延迟到枚举业务数据后才拒绝。
- 修复目标与要求：业务来源名单保持固定，目标占用名单独立维护；显式禁止透视目标作为后续来源。
- 验证方式：第二个透视表引用前一目标时在 Build 阶段失败；多个透视表引用同一业务 Sheet 正常成功，并覆盖配置顺序。

### FIX-002：提前校验目标工作表名称并统一错误路径

- [ ] 严重程度 MEDIUM；处理要求 SHOULD_FIX。
- 问题：目标 Sheet 名称仅检查非空，非法字符留到 `workbook.Worksheets.Add` 处理。
- 证据：`ExcelPivotTableDefinition.cs:38`、`ClosedXmlReportWriter.cs:80`。`TargetSheet="Bad/Sheet"` 构建成功；同步导出抛出原始 `ArgumentException`，异步导出包装为 `BingOfficesExportException`。
- 影响：同一输入具有不同错误分类和观察路径，而且在业务数据枚举后才失败。
- 修复目标与要求：复用工作表命名规则提前验证长度、非法字符及必要的名称约束；保证同步/异步行为一致。校验名称的规则应集中复用，不新建一套不一致规则。
- 验证方式：非法名称、超长名称、合法中文名称和大小写冲突；核对枚举次数、目标内容和异常分类。

### FIX-003：校验透视结果的展开边界

- [ ] 严重程度 MEDIUM；处理要求 SHOULD_FIX。
- 问题：只检查目标起点在 XLSX 内，没有为行字段、数值列、表头和总计保留空间。
- 证据：`ClosedXmlReportWriter.cs:26`；两条不同分组的数据使用 `TargetColumn=16383` 或 `TargetRow=1048575` 均导出成功，透视 location 分别为 `XFD1`、`A1048576`。
- 影响：合法锚点不能保证结果能在刷新时展开。本次未用 Excel 客户端打开该文件，因此不声称已经验证了客户端具体报错或修复行为。
- 修复目标与要求：定义首期布局的必要宽度和行数预算，在序列化前拒绝放不下的结果；考虑分组数、空键、总计与整数溢出。
- 验证方式：末行/末列失败、恰好容纳成功，验证目标流/文件未被改变；补充客户端展开或等价布局证据。

### FIX-004：补齐透视请求的验收矩阵

- [ ] 严重程度 MEDIUM；处理要求 SHOULD_FIX。
- 问题：`PivotTableContractTest` 当前双 TFM 各 10 项，覆盖同步流成功/失败与预取消；未覆盖计划要求的透视目标真实文件保护及相关资源链。
