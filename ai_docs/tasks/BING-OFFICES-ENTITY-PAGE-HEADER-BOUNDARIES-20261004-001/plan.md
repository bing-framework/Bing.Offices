# Entity 重复页眉标记与表头边界

Task ID：`BING-OFFICES-ENTITY-PAGE-HEADER-BOUNDARIES-20261004-001`

## 目标

完成前一阶段审查建议 DESIGN-001、DESIGN-002，不改变公共 API。NPOI XLS/XLSX 和 ClosedXML XLSX 使用同一行为契约。

## 行为约定

1. 页眉标记文本是该列表标记列的保留值。导出明细写出的单元格经导入同样的文本规范化后若等于 marker，输出目标前报带原始坐标的配置错误。导入时异常标记不接纳为明细。
2. 无列表表头时，marker 列必须位于最终明细物理列范围外；否则无法区分后续页眉与同列明细。这一条件在命名起点解析及最终列计划形成后检查。
3. 有列表表头时，Fluent `Cell` 可以写入同一标题及样式，但不能改变最终物理列计划中的标题。首页和每个复制页均检查，防止按页值工厂只改写后续页。Fluent `Merge` 不得触及列表表头的任何列；表头之外的单据头合并继续允许。
4. 导入对复制页的列表表头逐列核对，防止一个出现在预期行的业务 marker 被当成有效页眉。保持现有 marker、分页、分组及资源边界。

## 实施与验收

- 共享实体页眉校验承接无表头 marker 列及复制表头核对；两个 Provider 在最终列计划上执行相同检查。
- 补 NPOI HSSF/XSSF、ClosedXML XLSX 职责测试：固定/动态/计算列碰撞、转换后文本、首/后续页标题、合并、命名起点、输出流完整和导入错误坐标。
- 更新中文 XML 注释、能力文档、执行记录及生产符号到测试方法映射。
- 公共 API 双 TFM 成员差异为零；依次运行职责测试、受影响合同、Release `Category!=Large`、本地包消费者、API 身份比较、编码与差异检查。
