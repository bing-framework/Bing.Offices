# 透视来源数据与公式取值合同

Task ID：`BING-OFFICES-PIVOT-SOURCE-CONTRACT-20261005-001`

## 目标与真实证据

继续最新 TODO 的 D-001，在高级透视扩展之前固化 MVP 来源输入合同。现有 ClosedXML 单行字段/单 Sum 路径已真实输出缓存，但 `ClosedXmlReportWriter.ApplyPivotTables` 通过 `IXLCell.Value` 读取来源，会执行引擎支持的公式，与“不计算公式”的文案不一致。

从上一阶段最终 NuGet 包运行实际探针：`=1+2` 在同步/异步输出的缓存中为数值 3；`=NO_SUCH_FUNCTION(1)` 为配置错误。引擎单元格从 NeedsRecalculation=true、空缓存变成数值 3。探针先因匿名类型不满足 new()、跨项目共享 assets 参数而构建失败，改成公开模型和隔离包消费后成功；这些构建错误不是生产失败。

当前预检还把来源表头、空数据行、非数值求和等错误只写入消息，没有携带原始单元格坐标。数据合同和直接测试不足；并非缺少另一个透视接口或公式引擎。

## 合同与兼容性

- 来源包含一行非空、唯一表头和至少一行数据；字段比较继续忽略大小写，表头不自动修剪或重命名。
- 来源区域内公式在任何表头、分组、数值取值和缓存创建之前拒绝，返回现有 ConfigurationInvalid/Preflight，并携带来源 Sheet、原始一基行列及透视名称。新公式和有/无缓存的模板公式执行相同规则。不计算公式，也不把可能过期的缓存当作无条件有效输入。
- 来源区域外的公式继续按既有 Workbook 规则保留；自动字典文本以等号开头的现有行为不变。
- 拒绝完整空数据行以及来源 Excel 错误单元格；错误定位到相应来源单元格。模板中的来源公式及错误同样处理。
- 空分组键允许，并占一个结果行。数值、文本、日期、布尔分组继续保持单元格类型；文本比较及展开预算沿用现有规则。
- 非空求和值必须是真实数值；数字文本、日期、布尔不能隐式参与 Sum。空金额可忽略，但至少一个数值。不自行把 Excel 双精度存储升级为 decimal 精确聚合；应用对金额精度负责。
- 现有纯值来源、请求快照、Sheet 顺序、辅助名称分配和目标范围预算保持原有行为。所有公开类型、构造与签名不变；本阶段公共成员差异应为零。
- 迁移：先由应用或显式公式计算接口计算，然后把需要透视的数据写为字面值。后续若支持公式缓存，需要独立可选择策略及刷新合同，不扩大本阶段承诺。

风险：只有来源内公式及错误的行为明确收紧，需要迁移说明；使用已用单元格扫描，避免为了拒绝公式遍历整个格式最大矩形。

验收：所有失败发生在目标流序列化之前；无引擎隐式公式求值；错误携带正确来源坐标；纯值成功结构及资源合同不回退。
